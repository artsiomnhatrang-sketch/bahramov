**Что сделано**

  1399740228966212), сценарий «Доступ к Threads API». Аккаунт разработчика

  человека: нашла комментарий, сочинила текст, опубликовала.

**Решённые грабли**

- Кнопку «Сгенерировать маркер доступа» **нельзя нажать программно** — проверено
  по сетевым запросам: при синтетическом клике не уходит ни одного обращения
  к серверу. Окно согласия открывается отдельным окном Chrome.
- Комментарий-ответ на наш ответ лежит в `/conversation`, а не в `/replies` —
  из-за этого автоответчик сначала не видел продолжение диалога.
- У локального агента и облака были бы **разные журналы** → два ответа на один
  комментарий. Переделано: отвеченное определяется по самой ветке.

**Починена сеть облачных routines**

Причина многомесячной поломки оказалась одна: у окружения
`env_01PfQ3cxmUjM6mZJykd3VVXv` стоял Network access = «Trusted» (только менеджеры
пакетов). Переведено на **Custom** с `graph.threads.net` и `api.telegram.org`.
Проверено практически: облако прочитало комментарии Threads и доставило сообщение
в Telegram (`"ok":true, message_id: 6`). **Запись «облако режет весь исходящий
HTTPS» больше не верна.** Токены — в Environment variables окружения.

**Экономия лимита (тариф Pro)**

Облачная routine автоответов создана, проверена и **выключена** по решению
владельца: минимальный интервал routine — 1 час, каждый запуск это полноценная
сессия даже при отсутствии комментариев. Локальный агент почти бесплатен —
модель вызывается только при реальном комментарии, холостые проверки не стоят
ничего. На 12.09 поставлено напоминание в Telegram: посчитать долю ночных
комментариев и решить, включать ли облако обратно.

**Wordstat вернулся в работу — и прежний диагноз оказался неверным.**

чей сертификат не покрывает это имя, а по пути /v1/topRequests там 404.
API переехал в Yandex Cloud Search API. Сервисный аккаунт и ключ созданы
(лежат в .env), но упёрлись в непривязанный платёжный аккаунт. Решение:
снимать частотность через браузер — бесплатно и без карты.

## 2026-09-02 — SEO по фактическим данным: CTR-пакет и коммерческая релевантность

вместо обычных 40) и посчитали структуру спроса:

| Показатель | Факт за 30 дней |
|---|---|
| Показы | 3687 |
| Клики | 140 (CTR 3,8%) |
| Околокоммерческих запросов из 500 | 14 (~2% показов) |

**Главный вывод — сайт ловит не тот спрос.** 98% показов приходится на

они не покупают разбан за 10 000 ₽ даже с первого места. Прямых коммерческих
запросов («разблокировка инстаграм цена», «заказать чат-бота») в выдаче нет вовсе.

## 2026-08-22 (вечер) — технический аудит: HTTPS, скорость, доступность

Сессия диагностическая, статьи не писались. Три агента параллельно:
живой сайт, on-page SEO, доступность и скорость. Коммит `4b19491`.

**Критичное — сайт отдавался по http:// с кодом 200 без редиректа.**
В GitHub Pages была снята галочка «Enforce HTTPS», хотя сертификат
Let's Encrypt выпущен и валиден. Это дубли всех 48 адресов в http-версии
и минус в ранжировании. В `CLAUDE.md` при этом значилось «HTTPS: включён» —
работающий https и принудительный это разные вещи.
Включено через API Pages (`PUT .../pages`, `https_enforced:true`), не через
веб-интерфейс. Проверка: `curl -sI http://bahramovai.com/` → 301. Цепочка
с www — 2 хопа, заканчивается на https, для Pages это норма и не чинится.

**Аналитика — чинили слепые зоны.**
- `/unblock/` (короткая ссылка из шапки Instagram) вела на статью **без UTM** —
  весь этот трафик падал в Метрику как прямые заходы. Метки проставлены:
  `instagram / bio / unblock`. У `/ig/` метки были изначально.
- Счётчик Метрики поставлен на `404.html` — раньше не было видно, по каким
  битым адресам приходят люди.

**Скорость — суммарно ~350 КБ на первый визит.**
- Шрифты: убраны начертания, которые в файле нигде не используются —
  Unbounded 900 (25 файлов), Inter 300 (17). Скрипт проверял каждый файл
  отдельно и держал 400/700 всегда (заголовки и `<strong>` жирные по умолчанию).

  Пережаты в 520×520 через Pillow → 72 и 55 КБ. На `about.html` это LCP-элемент.
  Запаса 2× DPR хватает. `photo.jpg` как og:image не трогали.
- `fetchpriority="high"` на hero-картинки, `preconnect` к шрифтам
  на offer/privacy/consent (там его не было).

**Доступность.**
- Тач-цели в шапке на мобильных: было 18 px высотой с зазором 11 px, стало 39 px.
  Текст не сдвинулся, проверено в Chrome на локальном сервере.

## Техдолг

- Мёртвый код в index.html: функция `switchTab`, CSS `.tabs/.tab-btn/#forwhom`,

- Git в примонтированной папке не может удалять свои `.lock` и `tmp_obj` файлы
  (`Operation not permitted`). Перед каждой git-операцией из-под ассистента
