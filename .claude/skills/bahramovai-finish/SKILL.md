# Завершение сессии bahramovai.com

Цель: следующий чат должен открыться и **сразу знать всё**, что было сделано
сегодня, без пересказа от Артёма. Всё, что не записано здесь, будет потеряно.

## Порядок действий

Выполняй сам, ничего не спрашивая по мелочам. Артём не работает с терминалом.

### 1. Собрать, что реально произошло за сессию

```bash
git log --oneline "$(git log -1 --format=%H --before='today 00:00' 2>/dev/null || echo HEAD~5)..HEAD"
git status --short
```

Не сочиняй итоги по памяти — сверяйся с диффами. Если что-то делалось руками
Артёма (вход в аккаунт, публикация, нажатие кнопок) — это тоже часть итога.

### 2. Переписать CONTEXT-NOW.md

Это **главный файл** — именно он подаётся в следующий чат автоматически
(хук SessionStart -> `scripts/session-context.sh`).

Держать **не длиннее ~50 строк**. Структура фиксированная:

```markdown
## Где остановились
**Обновлено:** YYYY-MM-DD (+07) · сайт: N статей + M страниц услуг
<2–6 пунктов: что сделано в последнюю сессию, с фактами и ID/коммитами>

## Ближайшие задачи
<нумерованный список с датами-ориентирами, самое важное сверху>

## Что заблокировано и почему
<то, что упирается в доступы Артёма или во внешние ограничения>
```

Правила для этого файла:
- Пиши **факты и цифры**, а не «поработали над SEO».
- Даты — абсолютные (не «через две недели», а «~06.09.2026»).
- Что уже неактуально — **удаляй**, не накапливай. Летопись живёт в STATUS.md.
- Если задача упёрлась в Артёма — обязательно в раздел «заблокировано»,
  с указанием, какое именно действие от него нужно.

### 3. Дописать секцию в STATUS.md

STATUS.md — летопись, растёт вниз. Новая секция вставляется **сверху**,
сразу после шапки, в формате `## YYYY-MM-DD — краткая тема сессии`.
Обновить дату в шапке файла.

Туда идут подробности, которым не место в компактном CONTEXT-NOW: почему
принято решение, что проверяли, какие цифры были до и после, где риск.

Если STATUS.md перевалил за ~500 строк — вынести секции старше двух месяцев
в `docs/STATUS-ARCHIVE.md` и оставить ссылку.

### 4. Обновить CLAUDE.md, если менялись правила или состав сайта

- новая статья -> раздел «Опубликованные статьи» + счётчик в заголовке;
- новое правило от Артёма -> в нужный раздел правил;
- закрытая или изменившаяся задача -> раздел TODO.

Не дублируй в CLAUDE.md то, что уже есть в CONTEXT-NOW: там — «сейчас»,
в CLAUDE.md — «всегда».

### 5. Проверки и пуш

```bash
./scripts/preflight.sh
```

Выход 1 — **не пушить**, сначала чинить. Затем показать Артёму дифф, дождаться
одобрения и запушить одним коммитом:

```bash
git add -A && git commit -m "docs: update session status" && git push
```

### 6. Отчитаться

Коротко: что сделано за сессию, что запушено, что осталось и что из этого
требует действий самого Артёма. Без пересказа процесса.

## Чего не делать

- Не запускать `publish-article.sh` — это делает Артём вручную.
- Не публиковать ничего во внешние каналы (Telegram, соцсети) без отдельного «да».
- Не писать в CONTEXT-NOW.md то, чего не проверил.
