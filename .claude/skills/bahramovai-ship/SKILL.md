# Проверить и выложить правку

Ритуал перед каждым пушем. Артём не должен помнить про скрипты — запускай сам.

## 1. Прогнать все проверки

```bash
./scripts/preflight.sh
```

Гоняет разом: битые ссылки и картинки, sitemap, stat-card, JSON-LD, RSS,
повторы между статьями, честность изменённых текстов.

**Выход 1 = не пушить.** Чинить и гонять заново. Не «обойти», не `--no-verify`.

Отдельные инструменты, если preflight что-то нашёл и нужны детали:

| Команда | Что показывает |
|---|---|
| `python3 scripts/site-audit.py` | подробный технический аудит |
| `python3 scripts/overlap-audit.py` | карта пересечений между статьями |
| `python3 scripts/content-audit.py --changed` | честность изменённых текстов |
| `python3 scripts/check-stat-cards.py` | карточки со статистикой |

## 2. Проверить, что затронуто лишнего

```bash
git status --short && git diff --stat
```

Особое внимание:
- **`sitemap.xml` — `lastmod` менять только там, где правился контент.** Если
  менялся только `<head>`, трогать lastmod нельзя: это ложный сигнал свежести
  по всему сайту.
- `feed.xml` руками не править — он генерится `python3 scripts/seo-sync.py`.
- Новая статья? Тогда нужны: карточка в `blog/index.html` (сверху нужного
  раздела + счётчик в `.cat-title`), запись в `sitemap.xml`, `seo-sync.py`,
  блок `data-hub-link` для кластера блокировок, запись в CLAUDE.md.

## 3. Показать дифф и дождаться одобрения

```bash
git diff
```

Артём одобряет дифф перед пушем — это правило проекта, не формальность.
Показывай содержательно: что изменилось и почему, а не простыню строк.

## 4. Запушить

```bash
git add -A && git commit -m "<осмысленное сообщение по-русски>" && git push
```

Сообщение коммита: что изменилось и **зачем**, а не «правки». Git-хук
`.githooks/pre-push` сам прогонит `preflight.sh --fast` и заблокирует
сломанный пуш.

Если хук не сработал после переустановки репозитория:

```bash
git config core.hooksPath .githooks
```

Если push не проходит из-за токена — новый на github.com/settings/tokens
(classic, repo scope), затем `git remote set-url origin https://ТОКЕН@github.com/artsiomnhatrang-sketch/bahramov.git`.

## Чего не делать

- Не запускать `publish-article.sh` — его запускает Артём вручную.
- Не пушить с `--no-verify`.
- Не менять `lastmod` «заодно».
