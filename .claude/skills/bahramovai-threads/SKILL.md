# Посты в Threads

Короткие посты из статей блога в @bahram.av через официальный Threads API.
Артём не должен ничего напоминать: тему предлагаешь ты, тексты пишешь ты,
публикуешь только после его «публикуй».

## Что уже настроено (не переспрашивать)

- Приложение Meta `bahramovai-threads`, права `threads_basic` + `threads_content_publish`.
- Токен в `.env` (`THREADS_ACCESS_TOKEN`), продлевается скриптом сам на 30-й день.
  Приложение пересоздавать не нужно никогда.
- Скрипт `scripts/threads-post.py`, черновики `threads/queue/`,
  опубликованное `threads/posted/`, журнал `threads/posted.json`.

## КОМАНДА «ПУБЛИКУЙ» — полный цикл без единого вопроса

Артём пишет **«публикуй»** (или «поехали», «работаем», «давай тредс») в новом
чате - это команда на весь цикл сразу. Ничего не переспрашивать, не предлагать
план, не ждать подтверждений. Само слово уже является разрешением на публикацию
в этот день, правило «без явного публикуй ничего не публикуется» им закрыто.

Порядок, строго по шагам, каждый доводить до конца:

1. **Цифры.** `python3 scripts/threads-stats.py --posts 12 --days 14`.
   Запомнить, что взлетело и что провалилось, но в чат вываливать таблицу
   не надо - только вывод в конце.
2. **Комментарии под своими постами (API).**
   `python3 scripts/threads-replies.py --list --posts 15` → ответить на все
   неотвеченные через `--reply ID --text "..."`. Согласие и «спасибо» ответа
   не требуют, вопрос и возражение - требуют.
3. **Лента действий (браузер).** `https://www.threads.com/activity/replies` →
   собрать ветки JS-фильтром → открыть те, где после реплики человека нашего
   ответа нет → ответить. Артём часто отвечает сам, второй ответ выглядит глупо.
4. **Новые ветки - минимум 15 за подход.** Искать по блокировкам; если свежих
   мало (проверено 14.09.2026: поиск по блокировкам отдаёт в основном старое),
   добирать из живых смежных кластеров:
   `упали охваты`, `охваты в инсте`, `боты подписываются`, `накрутка`,
   `ии агент`, `чат-бот для бизнеса`, `нужен таргетолог`, `клиентов нет`.
   Перед ответом сверяться с `threads/stalker-log.md`, чтобы не писать одному
   человеку дважды. Тексты каждый раз новые, тон через `/human`, без ссылок
   и картинок.
5. **Посты.** Пополнить `threads/ideas.md` из того, что встретилось в ветках,
   затем написать и опубликовать очередь дня - до 6 постов, интервал 3 часа,
   не меньше двух личных. Публиковать `scripts/threads-post.py --file ... --yes`
   по одному, а не пачкой.
6. **Записать и запушить.** Подход в `threads/stalker-log.md`, темы в
   `threads/ideas.md`, потом `./scripts/preflight.sh` → коммит → `git push`.
7. **Отчёт в конце.** Коротко: сколько ответов и кому, что опубликовано,
   какие закономерности видно по цифрам, что рекомендую дальше. Без пересказа
   процесса.

⚠️ Единственное, что останавливает цикл: **явный запрет Артёма** или
блокировка аккаунта. Технические проблемы (слипшийся текст, промах по кнопке,
зависшая вкладка) решаются по рецептам ниже, а не докладываются как препятствие.

## 0.0 Через API или через браузер — и как не жечь токены

Правило Артёма от 13.09.2026. Проверять на каждом шаге, а не вспоминать потом.

**Через API (дёшево, всегда предпочитать):**

| Задача | Команда |
|---|---|
| опубликовать пост | `python3 scripts/threads-post.py --file threads/queue/NN-имя.txt --yes` |
| прочитать комментарии под своими постами | `python3 scripts/threads-replies.py --list --posts 15` |
| ответить на комментарий под СВОИМ постом | `python3 scripts/threads-watcher.py --once` |
| статистика | `python3 scripts/threads-stats.py --posts 12 --days 14` |

**Только через браузер (API этого не умеет):**

- ответы в ЧУЖИХ ветках - Meta не отдаёт id чужих постов, проверено 07.09.2026;
- лента действий `activity/replies` - через API не видна вообще;
- закрепление поста в профиле - меню «...» у поста, пункт «Прикрепить к профилю»;
- правка профиля: имя, описание, ссылка, теги.

**Экономия токенов в браузере — обязательная часть работы:**

1. **Не делать скриншот ради проверки текста.** Скриншот около 2000 токенов,
   JS-запрос около 50. Проверять ввод так:

```js
const el=[...document.querySelectorAll('[contenteditable="true"]')].pop();
const t=el?el.innerText:'';
({длина:t.length, пробелов:(t.match(/ /g)||[]).length, начало:t.slice(0,40)})
```

2. **Читать ветки через `get_page_text`, а не скриншотом.** Скриншот нужен
   только когда непонятно, куда нажимать, или когда человек прислал картинку.
3. **Поиск целей — сразу JS-фильтром**, не выводить всю выдачу: собирать
   ссылки и первые 150 символов, отсеивая нерелевантное регуляркой.
4. **Батчить действия** через `browser_batch`: навигация, ожидание и чтение
   одним вызовом вместо трёх.
5. **Проверять факт отправки** тоже JS-запросом: поле пустое плюс текст
   появился в ветке.

## 0. Комментарии — проверять ОБА канала, отвечать всем

Правило Артёма от 11.09.2026: «проверяй все и отвечай всем по всем пунктам».
Просьба «ответь на комментарии» означает не один список, а два, и пока оба
не разобраны, работа не сделана.

**Канал 1 — комментарии под нашими постами.**

```bash
python3 scripts/threads-replies.py --list --posts 15
```

**Канал 2 — ответы людей на наши комментарии в ЧУЖИХ ветках.** Через API их
не видно вообще, только страница `https://www.threads.com/activity/replies`
в браузере. Именно здесь лежит самое ценное: там люди задают прямые вопросы
про цену и помощь. Прецедент 11.09: в ленте действий висели три вопроса
(«а сколько стоит такая услуга?», «гарантии даёте?», «можно написать вам
в директ?») — Артём ответил на них сам, а по первому проходу ассистент этот
канал вообще не открыл и отчитался, что неотвеченных нет.

Как разбирать ленту действий:
1. открыть `activity/replies`, снять список через `get_page_text`;
2. собрать ссылки на ветки скриптом в консоли страницы
   (`div[data-pressable-container]` → `a[href*="/post/"]`);
3. **открыть каждую ветку и посмотреть, есть ли уже наш ответ ПОСЛЕ реплики
   человека** — в ленте это не видно, а Артём часто отвечает сам, и второй
   ответ выглядит глупо;
4. ответить везде, где ответа нет. «Спасибо» и «понял» — закрыто, ответ
   не нужен; вопрос, возражение или новая деталь — нужен обязательно.

Отдельно: ответ на возражение пишем без спора. Если человек поправил нас
по фактам и прав, так и говорим — прецедент @larnakem, где порядок блокировки
оказался обратный нашему предположению.

## 0.5 Роль в ответах — продавец в стиле Alex Hormozi (правило от 11.09.2026)

Прямое указание Артёма: отвечать так, как отвечал бы **Alex Hormozi** —
профессиональный продавец и маркетолог. Это не про напор и не про скрипты,
это про порядок работы.

**Схема ответа человеку с покупательским намерением:**

1. **Квалифицировать, а не грузить.** Формулировка, которую Артём дал
   эталоном: «Позвольте я задам пару вопросов, чтобы лучше понять ситуацию,
   сэкономить время и все не рассказывать, а потом подберу то, что конкретно
   вам подойдет». Два вопроса, не пять, и оба про факты: сколько заявок,
   где они идут, кто отвечает сейчас.
2. **Ценность вперёд, деньги потом.** Сначала сказать, что человек может
   сделать бесплатно и сам, и только потом — что делается за деньги.
   По Хормози секреты раздают, продают внедрение. У Артёма это честно:
   половину действий по разбану человек и правда делает руками.
3. **Снять риск.** Не обещать результат, а называть условия: что входит,
   что бывает, если не получилось. Обещание гарантии — маркер мошенника
   в этой нише, им забиты те же ветки.
4. **Один понятный следующий шаг.** «Напишите в директ, разберу и скажу оба
   варианта» — одно действие, без вилки из трёх.
5. **Цену в комментарии не называть.** Разброс работ слишком большой,
   и цифра без разбора отпугивает. Цену Артём называет в личке сам.

**Уточнение от 12.09.2026: эта схема применяется в КАЖДОМ ответе в новой ветке,
а не только там, где человек готов купить.** Прямое указание Артёма. Практический
шаблон, который получился за день:

> два вопроса по факту (что дословно на экране, была ли кнопка обжалования)
> → короткий порядок действий, который человек делает сам и бесплатно
> → один следующий шаг

Приглашение в личку ставится там, где у человека бизнес и деньги на кону
(клиенты, заказы, рабочий аккаунт), и не ставится там, где его нет -
волонтёру или человеку без денег зовущий в директ ответ только вредит доверию.

⚠️ **Исключение из правила «без приглашений в личку».** Раньше действовало
жёсткое «никаких напишите в директ» — потому что под постами людей в панике
стоит очередь анонимов с «Лс» и авторы им не верят. Правило остаётся для тех,
у кого беда прямо сейчас. Но там, где человек **сам написал, что готов
купить** (`готов купить у вас рабочее решение`, `сколько стоит`, `ищу того,
кто сделает`), звать в директ можно и нужно — это не навязывание, а ответ
на его же запрос. Ссылок на сайт по-прежнему не ставим: 0 кликов за 14 дней.

## 2.5 Пополнить банк тем — до того, как писать тексты

Темы не придумываются на ходу, они копятся в `threads/ideas.md`.
Перед написанием постов открыть банк и **дописать в него новое** из четырёх
источников, а уже потом выбирать, о чём писать:

1. **Свои комментарии** — `python3 scripts/threads-replies.py --list --all --posts 15`.
   Вопрос, непонимание или несогласие в комментарии = готовая тема.
   Записывать дословной цитатой, а не пересказом.
   ⚠️ Комментарии от `@bahramovartem` — второй аккаунт самого Артёма,
   за спрос аудитории их не считать.
2. **Своя статистика** — что залетело, переписать другим углом.
   Один залетевший пост даёт 5–10 тем.
3. **Спрос в поиске** — формулировки из Wordstat (браузер,
   `wordstat.yandex.ru/?region=225&words=...`). Это вопросы аудитории,
   только замеренные цифрой.
4. **Мифы из своих статей** — «все советуют Х, это не работает».
   Спорить можно смело: за спиной текст статьи, а не мнение.
5. **Чужие комментарии** (техника «Сталкер», из канала @dima2x2) — зайти
   к 5–7 крупным авторам в теме соцсетей и безопасности аккаунтов, читать
   не посты, а **споры в комментариях**. Там лежит боль в живых словах.
   Это единственный источник, которого у нас нет в цифрах, — только руками.
   Записывать в банк дословно, с указанием, у кого подсмотрено.

Использованную тему пометить в банке `[опубликовано NN]`.

**Не брать из чужих методик** (разобран канал @dima2x2, 06.09.2026):

- **провокацию ради срача и хейт.** Ниша Артёма — доверие (люди отдают доступ
  к аккаунту), скандальному автору аккаунт восстанавливать не понесут;
- **«актуализировать боль так, чтобы не покупать казалось бредом».** К нам
  приходят люди в панике от угона — давить на страх тут нельзя ни этически,
  ни практически: паникующий человек уходит к тому, кто говорит спокойно;
- **эмоциональное слово в начале заголовка** (Капец / Жесть / Боже). У Артёма
  это уже проверено на своих постах и провалилось: `⚠️ Будьте осторожны ⚠️` — 73 показа;
- **чужие цифры** (+426 подписчиков, 90% веток залетают, 100k охвата) — это
  результаты другого автора в другой нише, в наши тексты они не идут.

**Рабочая схема:** личный вход (что со мной происходит / что мне пишут) →
одна мысль по делу → вопрос читателю. Экспертиза прячется внутрь истории,
а не выносится в заголовок.

⚠️ **Личный вход не значит выдуманный.** Опираться только на правду: он
восстанавливает аккаунты клиентам, живёт в Нячанге, к нему приходят с угнанными
профилями. **Артёма лично НЕ взламывали** — в статье №44 описаны случаи его
КЛИЕНТОВ, а не его собственные. Прецедент 06.09.2026: пост «меня самого
взломали» был написан по ошибочному прочтению записи в CLAUDE.md и снят
владельцем до публикации.

**Правило:** личный эпизод в посте берётся только из прямых слов Артёма
в чате. Не из статьи, не из записи в контексте, не по смыслу. Если эпизода
нет — строить пост на его мнении и на том, что ему пишут, а не на выдуманном
случае из его жизни.

## 2.7 Разведка ниши — что залетает у других в IT и ИИ (с 15.09.2026)

Прямое требование Артёма: не ждать от него тем, а приносить готовые предложения,
опираясь на то, что **реально работает у соседей по нише**. Делать в каждую
сессию перед написанием постов.

Как снимать (один JS-запрос на выдачу поиска, без скриншотов):

```js
const out=[];document.querySelectorAll('div[data-pressable-container]').forEach(d=>{
 const a=[...d.querySelectorAll('a[href*="/post/"]')].map(x=>x.getAttribute('href'))[0];
 if(!a)return;const t=d.innerText;
 const nums=(t.match(/\n(\d+)\n/g)||[]).map(x=>+x.trim());
 out.push({a,max:nums.length?Math.max(...nums):0,t:t.replace(/\n+/g,' | ').slice(0,190)})});
out.sort((x,y)=>y.max-x.max);out.slice(0,7).map(o=>o.max+' :: '+o.t)
```

Запросы: `ии агенты`, `нейросети`, `автоматизация`, `вайб кодинг`, `чат-бот`,
`n8n`, `ии креатор`. Смотреть не темы, а **структуру**: первая строка, длина,
есть ли список, чем заканчивается.

**Замер 15.09.2026 — четыре формата, которые собирают сотни реакций:**

| Формат | Пример из ниши | Реакций |
|---|---|---|
| стек инструментов списком, без воды | `Claude пишет сценарии, Kling визуал, Artlist музыка` | 372 |
| резкое мнение против хайпа своей же ниши | `вайб кодинг или нормальный кодинг - всё хуйня, продайте то, что накодили` | 332 |
| прогноз с личной тревогой | `человечеству будет тяжело в ближайшие 5 лет` | 300 |
| вопрос-проверка хайпа | `кому-нибудь AI-агент уже заработал денег? Прям денег` | 89 лайков, 90 ответов |

**Чего в залетевших постах нет вообще:** инструкций «как сделать», призывов
писать слово в комментарии, эмодзи-предупреждений, ссылок. Ровно то, что
у Артёма проваливалось (`Напиши Доступ в комменты` - 34 показа).

⚠️ **Копируем структуру, а не содержание.** Пост-близнец чужого текста
в этой нише считывают мгновенно. Берём форму и наполняем своей фактурой.

**Наш козырь, которого нет ни у кого в этих ветках.** Вся ниша обсуждает,
что агент умеет, и никто не говорит, **чем автоматизация кончается для
аккаунта**. У Артёма это измерено: рассылка ChatPlace на 3214 человек дала
146 и 138 отключений в июле-августе, после отключения рассылки в сентябре
осталось 15. Плюс первая продажа с сайта пришла с YouTube, а не из Instagram
с 6846 подписчиками, где кликов по ссылке за месяц - два. Эти цифры - его,
проверяемые, и они превращают любой формат из таблицы в пост, который
больше никто написать не может.

## 3. Предложить темы и написать посты

Источник — статьи кластера безопасности (разблокировки, взлом, фишинг,
проверки личности, блокировки мессенджеров). **Открыть статью и писать по ней**,
а не по памяти: цифры и формулировки должны совпадать с текстом статьи.

Правила текста:
- **до 500 символов**, это жёсткий лимит платформы;
- на «вы», тон нейтральный — как в статьях (см. CLAUDE.md, п. 12);
- ни одной цифры и ни одной механики Meta/Telegram сверх того, что есть в статье;
  цифра без источника в статье — в пост не идёт;
- **ссылка на сайт — редко.** Замер 06.09.2026: за 21 день 0 кликов по ссылкам.
  Threads трафика на сайт пока не даёт, цель поста — комментарий и переписка
  в личке. Если ссылка всё же уместна — с `?utm_source=threads`;
- имя владельца, если упоминается, — **Артём Бахрамов**.

Сохранять по одному файлу на пост: `threads/queue/NN-короткое-имя.txt`.
Нумерация продолжает существующую.

Предлагать **3–4 темы с обоснованием от цифр** («прошлый пост с личной подводкой
дал вчетверо больше — беру этот угол»), а не просто список заголовков.

## 3.5 Две проверки перед тем, как отдать текст

**Сегментирующее слово в первой строке.** В первых словах должно быть видно,
для кого это написано: «если у вас увели телеграм», «кому блокировали инстаграм».
Без него пост собирает случайных людей — пост «Сегодня был на массаже» дал
5602 показа, и все комментарии ушли в обсуждение эрекции: охват без единого
вопроса по услугам. Личный вход остаётся, но внутри поста должно быть ясно,
к кому обращаются.

**Баланс ленты — три типа постов, не один.** Проверять по последним 10 постам:

| Тип | Зачем | Как сейчас |
|---|---|---|
| про личность | доверие, охват | работает (4500–5600 показов) |
| про экспертизу | «он в этом разбирается» | пока проваливается, кроме «синей галочки» — 2793 |
| про то, что он делает за деньги | без этого не придут | почти нет, а прямой призыв дал 35 показов |

Если в последних 10 постах чего-то из трёх нет — следующий пост берём этого типа.
Продуктовый пост писать не призывом («напиши в комменты»), а разбором случая
клиента: что было, что сделали, чем кончилось.

## 4. Показать Артёму и дождаться «публикуй»

```bash
python3 scripts/threads-post.py --all --dry-run
```

Покажет длину каждого поста и не отправит ничего. Тексты вывести в чат целиком.

**Без явного «публикуй» ничего не публикуется.** Это не настройка и не перестраховка:
пост уходит в публичный аккаунт, связанный с Instagram, который Артёму уже блокировали.

## 5. Опубликовать

```bash

```

Публикует всю очередь с паузами 30–50 минут (интервал случайный),
пишет журнал и переносит файлы в `threads/posted/`. Ссылки на посты вывести в чат.

Один пост отдельно:


## Темп — норма поднята 15.09.2026 по решению владельца

**До 6 постов в сутки, интервал между постами не меньше 3 часов.**

Это решение Артёма от 15.09.2026, принятое вопреки замеру ниже. Ассистент
возражение высказал один раз и дальше исполняет: шесть постов при интервале
3 часа занимают день целиком, с 08:00 до 23:00 по Нячангу. **Интервал важнее
количества и не сокращается ни при каких условиях.** Если за неделю такого
темпа средний охват на пост упадёт против предыдущей недели - вернуть 3 поста
и сказать об этом Артёму с цифрами.

Прежняя договорённость о 3–4 постах проверена практикой 05.09 и провалилась.
Четыре поста за два часа (12:42, 13:26, 13:50, 14:45) дали такую картину:

| Время | Показы |
|---|---|
| 12:42 | 211 |
| 13:26 | 275 |
| 13:50 | **1** |
| 14:45 | **1** |

После третьего поста лента перестала показывать их вообще. Технический потолок
Meta — 250 постов в сутки, но это лимит API, а не лимит алгоритма: охват режется
намного раньше. В тот же день был заблокирован аккаунт разработчика Meta
с формулировкой «необычные действия» — снялось подтверждением личности.

Ключевое здесь — не количество, а плотность: все четыре поста ушли за два часа.
07.09 постов было три, но врозь по времени, и обвала не случилось: 2236 / 102 / 54.

Пачкой не публиковать никогда - именно плотность и убивает охват.

И более сильный рычаг, чем темп: **жанр**. Личные посты дают тысячи показов,
экспертные — десятки, разница в сотни раз. При шести постах в день личных
должно быть не меньше двух, и ставить их первым и четвёртым - экспертные
едут на их охвате. Шесть экспертных подряд соберут сотню показов на всех.

⚠️ **Шесть постов в день - это шесть готовых черновиков каждый день.**
Очередь `threads/queue/` при таком темпе выгорает за двое суток, поэтому
банк тем (`threads/ideas.md`) пополняется в каждую сессию, до написания
текстов. Если готовых тем меньше шести - публикуем столько, сколько есть
хороших, и не добиваем слабыми: один проходной пост стоит дешевле, чем
день просевшего охвата.

## 6. Вторая дорожка — ответы людям в чужих ветках

Своих постов мало кто видит, пока охват зажат, а под чужим постом с охватом
в тысячи наш ответ видят все читатели ветки. **Это отдельная рабочая дорожка,
и «поработаем с Threads» включает её тоже.**

Кого ищем: людей, у которых **проблема прямо сейчас** — взломали Telegram,
заблокировали Instagram, не проходит проверка личности, увели канал.
Поиск в Threads по фразам живым языком, как пишут люди:
`взломали телеграм`, `взломали телегу`, `заблокировали инстаграм`,
`заблокировали аккаунт`, `восстановить инстаграм`, `угнали аккаунт`,
`не могу зайти в инстаграм`, `проверка личности инстаграм`.


**Порядок работы с целевой веткой (решение Артёма 11.09.2026):** в первом
ответе **ничего не продаём** — только рекомендация по существу, бесплатно
и конкретно. В директ зовём **вторым шагом**, когда человек ответил и
завязался разговор. Исключение — те, кто прямо написал, что готов купить
или ищет исполнителя: там сразу работает схема из раздела 0.5.

Как отвечаем:
- по делу и спокойно, первым шагом — что человеку сделать прямо сейчас;
- **не давить на панику и не обещать результат.** К нам приходят напуганные
  люди, обещание «верну за час» отпугивает сильнее, чем помогает;
- **ссылок в ответ не ставим вообще** (решение Артёма 11.09.2026). Две причины:
  замер показал 0 кликов по ссылкам в Threads за 14 дней, то есть пользы нет;
  а ограничение, которое регулярно прилетает на аккаунт, называется буквально
  «вы не можете делиться ссылками» — ссылка в чужой ветке бьёт ровно в эту
  мишень. Кому нужно больше, нажмёт на ник: там профиль и сайт;
- **картинок и скриншотов кейсов в чужие ветки не вставляем** (там же).
  Приход в комментарии к человеку с блокировкой + скриншот «аккаунт
  разблокирован» — это дословно шаблон мошенников этой ниши, автомат видит
  шаблон, а не намерение. Кейсы живут только у себя: сторис, хайлайты, сайт;
- **пишем человеческим языком, в тоне Артёма** — скилл `/human` срабатывает
  сам, но здесь это обязательное условие, а не пожелание. Короткое тире вместо
  длинного, кавычек не ставим, без канцелярита и без структуры «во-первых,
  во-вторых». Читаться должен живой человек, а не бот: люди в комментариях
  мгновенно считывают машинный текст и перестают доверять;
- **тексты каждый раз новые.** Одинаковые комментарии под разными постами
  Meta читает как спам. Не переписывать один и тот же ответ под другого
  человека — писать заново от его ситуации;
- **до 14 ответов за подход, до 42 в день** (норма Артёма от 11.09.2026:
  14 утром, 14 днём, 14 вечером). Прежние 5–6 были перестраховкой, а не
  замером: единственная реальная блокировка 06.09 прилетела за опрос API
  каждые 3 минуты, к ручным комментариям отношения не имела. Между подходами
  несколько часов, внутри подхода не строчить очередью без пауз;
- ⚠️ при таком темпе **решает не количество, а однотипность**. Каждый текст
  пишется заново под ситуацию человека; одинаковые или почти одинаковые
  комментарии под разными постами читаются как спам быстрее, чем объём.

Технически: официальный API умеет отвечать только под своими постами,
поэтому чужие ветки — **только через браузер** (открыть ветку → поле
«Ответьте …» → текст → стрелка).

⚠️ **Координаты кликов не равны CSS-координатам** (правило от 14.09.2026).
`window.innerWidth` отдаёт 1512, а клики и скриншоты живут в кадре 1568 -
промах в 30-40 пикселей, клик уходит вхолостую, и текст молча остаётся в поле.
Считать так: `k = ширина_кадра / window.innerWidth` (кадр печатается в строке
`coordinate frame` у любого скриншота), все JS-координаты умножать на k.
Кадр меняется, если окно меняло размер, - пересчитывать, а не запоминать.

⚠️ **Кнопку отправки искать как `[role="button"]` шириной 36 правее поля.**
По `aria-label="Ответ"` находится иконка комментария под каждым постом ветки,
и клик уходит не туда. Если вместо отправки открылся полноэкранный композер
(заголовок «Ответ»), текст цел - жать «Опубликовать» в правом нижнем углу.

✅ **Текст в поле вводить вставкой, а не печатью** (правило от 14.09.2026).
`type` теряет пробелы и пунктуацию на любом вводе длиннее ~20 символов -
14.09 слиплись все попытки подряд, включая печать кусками по 45 символов
и после перезагрузки. Рабочий способ - событие paste:

```js
const el=[...document.querySelectorAll('[contenteditable="true"]')].pop();
el.focus();
const dt=new DataTransfer(); dt.setData('text/plain', ТЕКСТ);
el.dispatchEvent(new ClipboardEvent('paste',{clipboardData:dt,bubbles:true,cancelable:true}));
```

Порядок: navigate → 6 сек → координаты поля JS → клик в поле → 2 сек → paste →
клик в поле ещё раз → клик по стрелке на (1070-1073, нижняя граница поля + 5).
Вставка дописывается к тому, что уже в поле, поэтому перед ней страница должна
быть свежей. Промах по стрелке на 3-4 пикселя = клик вхолостую; если два клика
подряд не сработали, снять точные координаты зумом узкого региона вокруг кнопки.
Программный `.click()` и cmd+Enter не работают.

⚠️ **Перенос строки в поле ответа = отправка.** Текст с пустыми строками
уходит по первому же переносу, остаток теряется (поймали 08.09 на @altyn_nurich:
опубликовался один первый абзац). **Ответ писать одним абзацем, без переносов
строк вообще** — 500 символов сплошным текстом читаются нормально.
⚠️ **Пробелы слипаются на каждом первом длинном вводе** (проверено 12.09.2026:
восемь ответов подряд, слиплись все восемь). Рабочий порядок: напечатать текст,
затем **отдельными вызовами** нажать cmd+a и Delete - в одном батче с печатью
они не успевают примениться, и текст удваивается, - затем напечатать тот же
текст заново. Со второго раза пробелы на месте.

⚠️ **Очистка поля: cmd+a и Delete работают не всегда.** 13.09.2026 в двух
ветках подряд они перестали применяться вовсе, текст копился и удваивался.
Что выяснилось: клавиатурные события доходят до поля только после клика
**по координате внутри поля**, а не по ref из find. Рабочий порядок на такой
случай: скриншот (найти поле) → клик по координате в поле → Backspace
с repeat по 100 до нуля → печать текста заново. JS-способы (execCommand
selectAll/delete/insertText, Selection API) на composer Threads не работают -
проверено, не тратить на них вызовы.

⚠️ **Проверять результат JS-запросом, а не скриншотом** (правило от 13.09.2026,
экономит около 2000 токенов на каждой проверке):

```js
const el=[...document.querySelectorAll('[contenteditable="true"]')].pop();
const t=el?el.innerText:'';
({длина:t.length, пробелов:(t.match(/ /g)||[]).length, начало:t.slice(0,40)})
```

Слипание видно по числу пробелов (около нуля), обрезанное начало - по длине
меньше ожидаемой. Оба дефекта ловятся надёжнее, чем глазами по картинке.
Скриншот нужен только когда непонятно, куда нажимать.

Каждый подход записывать в `threads/stalker-log.md`: кому, о чём была боль,
что ответили (ссылок с 11.09.2026 не ставим — графу «ссылка» не заполняем). Там же лежит очередь на следующий подход и вся история —
перед новым подходом прочитать, чтобы не писать одному человеку дважды.
