## Как добавить новую статью (workflow)
1. Создать blog/[имя-файла].html в дизайне сайта
2. SEO: description (155-160 символов), canonical, Open Graph, JSON-LD Article
3. Обновить blog/index.html — блог разбит на 4 раздела (id: #razblokirovki, #messengery, #prodvizhenie, #ai-assistenty). Добавлять карточку СВЕРХУ нужного раздела (внутри его .posts-grid) и увеличить счётчик «N статей» в .cat-title этого раздела. Юрстраница usloviya-okazaniya-uslug.html в листинг НЕ входит.
4. Обновить sitemap.xml — добавить новую страницу с lastmod=сегодняшняя дата

4b. Если статья входит в кластер «Блокировки Instagram» — добавить в начало тела блок `<div data-hub-link>` со ссылкой на hub-страницу (скопировать из любой статьи кластера) и поставить ссылку на новую статью в самом hub'е
5. git add . && git commit -m "описание" && git push
6. После пуша — открыть DISTRIBUTION-PLAN.md и пройтись по чеклисту распространения
7. ОБЯЗАТЕЛЬНО обновить `ARTICLES.md` — добавить статью в конец списка с актуальным номером и обновить счётчик в заголовке файла. В `CLAUDE.md` статьи больше не перечисляются.

**Про цифры в статьях:** в уже опубликованных материалах цифры реальные, из

**Автопроверка при пуше.** В репозитории настроен git-хук `.githooks/pre-push`
(включён через `git config core.hooksPath .githooks`). Он сам гоняет

ссылки, разметка или sitemap. Быстрый режим пропускает только проверку внешних
ссылок (единственная сетевая часть). Обойти в крайнем случае: `git push --no-verify`.

Если хук не срабатывает после клонирования репозитория заново — включить одной
командой: `git config core.hooksPath .githooks`

## Правила работы с Claude в чате
1. **Артём руками не делает ничего — ни терминал, ни интерфейсы.** Указание 13.09.2026: «я сам руками ничего не делаю, в самых крайних случаях только». Ассистент работает сам: терминал и скрипты, API (Вебмастер, Метрика, Threads, Instagram, Wordstat), браузер через Claude in Chrome (`mcp__claude-in-chrome__*` — Артём залогинен в Google, Яндексе, Meta) и, если нужно, экран Mac через `mcp__computer-use__*`. Задача «зайди в панель и настрой» — это работа ассистента, а не инструкция для Артёма. Просить его сделать что-то руками можно только когда иначе никак: ввод пароля, подтверждение личности, оплата, капча, кнопка выдачи токена в дашборде Meta.
2. **Начало сессии:** контекст приходит сам (хук SessionStart). Ничего просить у Артёма не нужно. Если сводки нет — прочитать `CONTEXT-NOW.md`.
3. **Конец сессии:** применить скилл `/bahramovai-finish` — он обновит CONTEXT-NOW.md и STATUS.md, прогонит проверки и запушит.
4. Перед новой статьёй: `./scripts/preflight.sh --tema "..."` (сверка на дубль) + фактчек по быстрым темам (Telegram/WhatsApp/Meta/регуляторка). Если тема занята — предложить усиление существующей статьи, а не новый файл.
5. **Доводить задачу до конца самому, не останавливаясь на вопросе «пушить?»** (указание Артёма 13.09.2026: «делай всё что нужно сразу, не жди»). Порядок: `./scripts/preflight.sh` → коммит → `git push` → проверить, что правка видна на живом сайте, и только потом отчитаться. Дифф показывать в отчёте ПОСЛЕ, а не спрашивать разрешение ДО. Прецедент: правки читаемости 13.09 были готовы локально, но не выложены — Артём открыл сайт и увидел старую версию. Спрашивать заранее только там, где действие необратимо или уходит наружу от его имени (посты, письма, удаление). publish-article.sh он по-прежнему запускает сам.
6. Артём не обязан помнить про скрипты и правила. Ассистент сам открывает нужный файл контекста и сам запускает проверки. Если Артём спрашивает «всё ли ок» — это запрос на preflight, а не на пересказ.
7. Отвечать по-русски, командами готовыми блоками. Не сваливать на Артёма то, что можно проверить самому.

## Префикс-кэш и экономия токенов (правило от 18.09.2026)

Полный регламент — `.claude/rules/prompt-caching.md`. Коротко:

- **Статика в начале промпта, динамика в конце.** Роль, правила и список
  инструментов — сверху; дата, номер новости, текст комментария, результаты
  поиска — снизу. Кэш совпадает по токенам от начала, правка в середине
  обнуляет всё, что после неё.
- **Список инструментов агента не меняется** внутри сессии (`tools:` в шапке
  агента, `--allowedTools` в скриптах). Глубина рассуждений и модель — тоже.
- **CLAUDE.md править дописыванием в конец.** Правка в середине пересчитывает
  весь хвост файла во всех будущих сессиях. Летопись — в `STATUS.md`,
  «сейчас» — в `CONTEXT-NOW.md`, сюда только постоянные правила.
- **Файлы читать кусками** (структура → нужный фрагмент), а не вываливать
  целиком в контекст.
