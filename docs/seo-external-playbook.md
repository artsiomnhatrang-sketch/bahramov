# Внешняя SEO-схема (ролик Sanskar Tiwari) — исходник и разбор под bahramovai.com

Источник: инструкция, которую Артём принёс 19.09.2026 из ролика на YouTube
(схема Sanskar Tiwari, текст выдан LLM). Ниже — дословный исходник и вердикт
по каждому пункту применительно к нашему сайту.

## Исходник (как есть)

```
CONTEXT & SEO ARCHITECTURE INSTRUCTIONS (Grounded in Sanskar Tiwari's Strategy):

1. STACK & FRAMEWORK
   - Framework: Next.js (SSR). Не чистый CSR/React SPA.
   - Routing: чистые, дружелюбные поисковику URL.

2. TECHNICAL SEO & INDEXING MANDATES
   - Explicit Canonical Tags на всех страницах (защита от дублей по ?ref=, фильтрам, меткам).
   - Dynamic Sitemap: sitemap.xml со всеми основными и keyword-лендингами.
   - Internal Footer Links: каждая динамическая/локализованная/keyword-страница
     линкуется прямо из футера, чтобы краулер её нашёл.

3. KEYWORD & LOCALIZATION STRATEGY (GEO / LANG ARBITRAGE)
   - Keyword Slug Matching: точная целевая фраза прямо в слаге URL, в том числе
     не-латиницей (арабский, кириллица), вместо префиксов /ar, /ru.
   - Page Personalization: H1/H2, мета и тело строятся вокруг long-tail запросов
     низкой конкуренции (KD <= 20).

4. UI/UX & DESIGN SYSTEM (PREVENT AI SLOP)
   - Типографика: современные чистые шрифты, например Outfit.
   - Эстетика: без «ИИ-вида» — без круглых ярко-синих кнопок, штампованных
     градиентов и избыточного блюра. Резкие края, чистая вёрстка.
```

## Разбор: что берём, что нет

| Пункт | Вердикт | Почему |
|---|---|---|
| Next.js + SSR | **Не берём** | У нас статический HTML на GitHub Pages. Для краулера статика = тот же готовый HTML, что и SSR, только быстрее и без сборки. Переезд на Next.js потребовал бы хостинга с Node, переписывания 53 страниц и риска потерять индексацию. Пункт решает проблему React-SPA, которой у нас нет. |
| Чистые URL | **Уже есть** | `/blog/имя.html`, `/uslugi/имя.html`, без параметров. |
| Canonical на всех страницах | **Уже есть** | Проверено: canonical стоит на всех контентных страницах. Без него только служебные (404, файлы верификации Google и Яндекса) — им он и не нужен. |
| sitemap.xml | **Уже есть** | 53 URL, обновляется при каждой публикации. |
| **Ссылки из футера на все целевые страницы** | **Берём, это дыра** | В футере сейчас 6 ссылок: три контакта и три юридические. Ни одной ссылки на услуги и разделы блога. У нас 30 страниц вне индекса Google — включая обе страницы услуг. Футер на 53 страницах = 53 внутренние ссылки на каждую целевую страницу. Самая дешёвая правка из всей схемы. |
| **Точная фраза в слаге** | **Берём частично** | Слаги уже осмысленные транслитом (`instagram-blokirovki-may-2026`). Менять существующие нельзя — потеряем накопленные позиции и внешние ссылки. Правило — для НОВЫХ страниц: слаг = точная формулировка запроса из Wordstat. Кириллицу в слаг не берём: Яндекс её переварит, но ссылка в мессенджерах превращается в `%D0%B1%D0%BB...` и её перестают кликать. |
| **Long-tail с низкой конкуренцией в H1/мета/теле** | **Берём, уже частично делаем** | Это то же, чем занимается `scripts/yandex-stats.py` и правило 20 в CLAUDE.md. Схема добавляет строгость: одна страница = один точный запрос, и он стоит в H1 дословно. |
| Шрифт Outfit | **Не берём** | У нас Unbounded + Inter, дизайн-система устоявшаяся. Менять шрифт ради совета из ролика смысла нет. |
| Без «ИИ-вида» | **Уже соблюдено** | Чёрный фон, оранжевый #f4672a, резкие края, градиентов и блюра нет. |

## Чего в схеме нет, а у нас это главное

Схема — про то, как быстро проиндексировать НОВЫЙ сайт. Наше узкое место другое:

1. **Внешние ссылки.** Одна за всё время (Т-Банк, июль) при 44 статьях. Google
   держит 30 страниц вне индекса не из-за техники — техника у нас чистая, —
   а потому что у домена нет веса. Футерная перелинковка это смягчает, но не лечит.
2. **Возраст домена.** С 25.04.2026. Любая схема упирается в это.
3. **Канал.** Весь фактический трафик из Яндекса, схема заточена под Google.

Поэтому схему применяем как чеклист гигиены, а не как план роста.
